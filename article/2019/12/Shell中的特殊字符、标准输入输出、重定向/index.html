Shell中的特殊字符、标准输入输出、重定向

发表于 2019-12-03 分类于 Linux

推荐链接：

shell中的特殊字符大全

特殊字符

$ 变量展开

美元符号$ 用于 变量展开/引用 ，获取变量的值。

`…` 和 $() 命令替换

  • 反引号 `…` 用于 命令替换 ，执行反引号中的命令，并将其输出作为当前命令的参数。
  • $() 是更现代、推荐的替代写法（支持嵌套，可读性更好）。

'' 强引用

单引号 ''（强引用）： 会阻止（抑制）Shell 进行变量展开，引用内的所有特殊字符都失去特殊含义，被视为纯字面文本。

"" 弱引用

双引号 ""（弱引用）： 引用内部大部分特殊字符失去特殊含义，但 美元符号 $、反引号 `、反斜杠 \ 仍保留其特殊功能（允许变量展开和转义）。

管道符 |

管道 (Unix)

用于连接一系列命令，将前一个命令的标准输出（stdout）作为后一个命令的标准输入（stdin）。

等价于通过临时文件过渡：

&

两种常见用法：

  1. 在重定向中表示“等同于”的概念（例如 2>&1 表示将文件描述符 2 重定向到文件描述符 1 指向的地方）。
  2. 放在命令末尾，表示该命令转到后台执行。

标准输入输出

标准输入输出 、 重定向 、 Shell 输入/输出重定向

在执行 Shell 命令时，系统通常会自动打开三个标准文件：

  1. 标准输入 (stdin, 文件描述符 0)：通常对应终端键盘。
  2. 标准输出 (stdout, 文件描述符 1)：通常对应终端屏幕，用于输出正常数据。>/dev/null 等同于 1>/dev/null，系统默认是1 。
  3. 标准错误输出 (stderr, 文件描述符 2)：通常对应终端屏幕，用于输出错误信息。

重定向符 > 与 >>

  • >（覆盖重定向）： 将标准输出重定向到指定文件。若文件不存在则创建；若已存在则清空原内容。

    注意： > 相当于 1>，默认的 1 表示标准输出，不包含标准错误输出。

  • >>（追加重定向）： 将标准输出以追加方式重定向到指定文件，若文件不存在则创建，保留原内容。

重定向常见误区

cmd >a 2>a 和 cmd >a 2>&1

  • cmd >a 2>a：标准输出和标准错误输出分别重定向到文件 a。这意味着文件 a 会被打开两次，形成两个独立的写入管道，导致 stdout 和 stderr 互相覆盖，容易引起数据丢失或错乱。
  • cmd >a 2>&1：标准错误输出重定向到标准输出，而标准输出再重定向到文件 a。文件 a 只被打开一次，标准输出和标准错误输出共享同一个管道写入文件，安全且符合预期。

2>1 和 2>&1

  • 2>1：Shell 会把 1 误认为是一个名为 1 的普通文件，从而把错误信息输出到当前目录下一个叫 1 的文件里，而不是重定向到标准输出。
  • 2>&1：& 与 1 结合代表标准输出，能够正确实现将标准错误合并到标准输出。

重定向操作符的顺序陷阱

重定向的解析是从左到右进行的。 顺序写错会导致达不到预期的屏蔽效果。

  • 错误示范（2>&1 >/dev/null）：

    当解析器读到 2>&1 时，它并不知道后面标准输出要重定向到哪儿，此时标准输出依然指向终端。因此，标准错误先被定向到了终端，随后标准输出才被定向到了垃圾桶。

    结果： 错误信息依然会打印在屏幕上，只有正确输出被丢弃了。

  • 正确示范（>/dev/null 2>&1 或 &>/dev/null）：

    先将标准输出重定向到 /dev/null，紧接着把标准错误重定向到标准输出（此时标准输出已指向 /dev/null），从而实现所有输出统统静默。

空设备 /dev/null

/dev/null：空设备文件（俗称“黑洞”或“垃圾桶”），所有写入它的数据都会被丢弃。

使用 nohup 让程序在后台运行

相关链接： 百科 、 Linux nohup 命令 - 菜鸟 、 shell中的特殊字符大全

nohup（No Hang Up，不挂断）用于使命令忽略挂起信号（SIGHUP），防止终端关闭时进程随之停止。

核心特点：

  • 免疫 SIGHUP 信号：即使关闭远程 SSH 终端，进程也不会随之终止。
  • 默认输出：若未指定重定向，输出会被默认写入当前目录下的 nohup.out 文件。

拆解说明：

  • nohup：不挂断运行，使进程忽略 SIGHUP 信号。
  • >/dev/null：将标准输出重定向到空设备（丢弃正常日志）。
  • 2>&1：将标准错误重定向到标准输出（由于标准输出已指向空设备，错误日志也被一并丢弃）。
  • &：让进程在后台运行，释放当前终端。
