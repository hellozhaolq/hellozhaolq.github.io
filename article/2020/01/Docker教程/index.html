Docker Engine

介绍

https://docs.docker.com/engine/

Docker Engine 是一种开源容器化技术，用于构建应用程序并将其容器化。Docker Engine 采用客户端-服务器架构，包含以下组件：

  • 一个服务器端，运行着一个长期驻留的守护进程（daemon process）——dockerd。
  • 一系列 API，定义了程序与 Docker 守护进程进行交互及发送指令所需的接口。
  • 一个命令行界面（CLI）客户端——docker。

dockerd（守护进程）

https://docs.docker.com/reference/cli/dockerd/

守护进程配置文件

https://docs.docker.com/reference/cli/dockerd/#daemon-configuration-file

--config-file 选项用来指定 守护进程配置文件（支持以 JSON 格式设置守护进程的任何配置选项） 的存储路径：

  • Linux 下 Docker 守护进程配置文件默认位置 /etc/docker/daemon.json 。
  • Windows 下 Docker 守护进程配置文件默认位置 C:\ProgramData\docker\config\daemon.json 。
选项 说明
log-driver 新容器日志的默认驱动程序（默认为 json-file）。
log-opts 新容器日志配置选项。
"max-size": "500m" 单个容器日志文件的最大容量限制。当某个容器的当前日志文件达到 500MB 时，Docker 会自动将其切分（轮转/Rotate），并开一个新的文件继续写入。
"max-file": "10" 保留的最大日志文件数量。结合 max-size，这意味着一个容器最多只会保留 10 个 500MB 的日志文件（1个当前正在写的 + 9个历史备份）。当产生第 11 个文件时，最老的那个日志文件会被自动删除。
data-root 修改 Docker Root Dir（根数据存储目录），Linux 默认是 /var/lib/docker，Windows 默认是 C:\\ProgramData\\docker 。
live-restore 默认当 Docker 守护进程停止或重启时，所有容器都会被强制关闭。开启 live-restore 后，容器保持在线（不中断业务）。
mtu 设置默认 bridge 网络的 MTU 值（默认值为 1500）。
bip 指定 Docker 默认网桥 (docker0) 自身的 IP 地址和子网掩码。
fixed-cidr 在 bip 指定的子网范围内，限制容器自动获取 IP 地址的子网范围
如果不配置 fixed-cidr，Docker 会把 bip 整个子网（如 /16）全部用来给容器分配 IP。如果没有特殊需求且已经配置了 bip，该参数可以省略。
default-address-pools 含义：默认地址池。为用户自定义网络（如执行 docker network create 或使用 docker compose 时自动生成的网络）划定一个专属的 IP 地址范围。
"base": "172.30.0.0/16"【大池子】允许 Docker 使用的总网段范围为 172.30.0.0 ~ 172.30.255.255。
"size": 24【切片大小】每次新建网络时，从大池子里切出一个掩码为 /24 的子网（即拥有 256 个 IP 的标准 C 类网段）。
default-ulimits 为 Docker 容器内所有新启动的进程，设置最大可同时打开的文件描述符。
dns 为所有 Docker 容器设置 DNS 服务器（而不是继承宿主机）。
insecure-registries 非安全（明文 HTTP 或自签证书 HTTPS）的私有镜像仓库列表。
作用是：允许 Docker 客户端连接并使用那些“不安全”或没有配置权威 SSL 证书的私有镜像仓库（Docker Registry）
registry-mirrors Docker Registry （如 Docker Hub）的镜像（Mirror）服务器。

Swarm mode

https://docs.docker.com/engine/swarm/

https://www.runoob.com/docker/docker-swarm.html

https://github.com/yeasy/docker_practice/blob/master/swarm_mode/README.md

Docker 1.12 Swarm mode 已经内嵌入 Docker 引擎，成为了 docker 子命令 docker swarm。请注意与旧的 Docker Swarm 区分开来。

Swarm mode 内置 kv 存储功能，提供了众多的新特性，比如：具有容错能力的去中心化设计、内置服务发现、负载均衡、路由网格、动态伸缩、滚动更新、安全传输等。使得 Docker 原生的 Swarm 集群具备与 Mesos、Kubernetes 竞争的实力。
