TCP 建连成功但大请求卡死：一次 PMTU 黑洞问题排查

发表于 2023-12-09 分类于 其他

推荐链接：

故障现象

在调用接口或访问网页时，出现以下异常：

  • TCP 三次握手可以快速完成；
  • 小数据交互正常；
  • 当发送较大的 HTTP 请求，或接收较大的响应数据时，连接出现卡死；
  • 长时间无响应，最终 Connection timeout 。

典型表现：TCP 连接建立成功，但数据传输阶段异常。

这类问题容易被误判为服务端故障、网络不通或应用超时，但实际上可能是网络路径中的 MTU 不匹配导致的 PMTU 黑洞问题。

PMTU 黑洞

https://en.wikipedia.org/wiki/Path_MTU_Discovery

概念 全称 解释与说明
MTU Maximum Transmission Unit（最大传输单元） 网络层（IP层）一次允许通过的最大数据包大小（含IP头、TCP/UDP头、数据）。 TCP 协议下：MTU = 20字节(IP头) + 20字节(TCP头) + MSS。 ICMP 协议下：MTU = 20字节(IP头) + 8字节(ICMP头) + ICMP数据区(Payload，即 ping -s 值) 标准以太网默认为 1500 字节。
MSS Maximum Segment Size（最大报文段长度） 传输层（TCP层）数据包能携带的纯数据净容量。 标准以太网 MSS 默认为 1460 字节。

PMTU（Path Maximum Transmission Unit，路径最大传输单元）：指数据包从源端到目标端经过的完整网络路径中，能够传输的最大 IP 数据包长度。它由整个链路中 MTU 最小的网络节点决定，而不是由通信双方主机自身的网络接口决定。

在 TCP 连接建立阶段，通信双方会通过 SYN 和 SYN-ACK 报文中的 Options 字段交换各自基于本地 MTU 计算得到的 MSS（Maximum Segment Size，最大报文段长度）。需要注意的是，TCP MSS 是双向独立协商的：客户端和服务端分别声明自己能够接收的最大 TCP Payload 大小，发送方后续发送数据时会依据对端声明的 MSS 进行限制。

然而，在实际网络环境中，例如 VPN 隧道、Docker 虚拟网络、云厂商 Overlay 网络、网关设备或防火墙设备等场景，由于额外封装或链路限制，中间网络的实际 MTU 可能小于标准以太网的 1500 字节。当 TCP 按照握手阶段协商出的默认 MSS（例如基于 1500 MTU 计算出的 1460 字节）发送数据时，IP 层通常会携带 DF（Don’t Fragment，禁止分片） 标志，避免数据包被分片。

如果中间链路无法承载该数据包，网络设备会直接丢弃报文，并尝试返回 ICMP Fragmentation Needed 消息，通知发送端降低报文大小，从而触发 路径 MTU 发现机制（PMTUD） 进行调整。

但如果该 ICMP 报文被防火墙、安全策略或中间网络设备过滤丢弃，发送端将无法感知实际路径 MTU 已降低，仍会持续发送超过链路承载能力的大数据包。由于这些数据包不断被中间设备丢弃，TCP 无法收到 ACK，只能重复发送相同报文，最终导致连接超时。

这种现象称为 PMTU 黑洞（PMTU Black Hole）。

PMTU 黑洞通常表现为：TCP 三次握手、小数据请求、心跳等小报文均正常，但在传输大文件、大响应或大数据载荷时出现卡顿、持续重传，最终连接超时断开。 其本质原因是路径 MTU 小于通信双方根据 MSS 推断出的发送大小，而 PMTUD 又因 ICMP 不可达而无法完成动态调整。

故障排查过程

应用层确认 TCP 是否建立成功（curl -v）

确认是否存在 DNS、端口或 TCP 建连问题。

看到 Connected to baidu.com 说明：

  • DNS 解析正常；
  • TCP 三次握手成功；
  • 网络端口可达。

如果随后 HTTP 请求发送后一直等待，说明问题不在连接建立阶段，而是在数据传输阶段。

抓包 (tcpdump)

在宿主机或容器内抓取发往目标 IP 的流量包，通过抓包观察实际 TCP 数据传输情况。

典型异常现象：

  • SYN / ACK 握手正常；
  • 小数据包正常（如握手包 SYN、ACK）；
  • 大数据包发送后，出现大量：TCP Retransmission（TCP 重传），且收不到对端的 ACK；

说明：TCP 数据包可能在链路中被丢弃。

结合“大请求卡死”的现象，高度怀疑 MTU 限制 / PMTU 黑洞 问题。

检查网络出口和 MTU 配置

确认数据实际经过哪些网络接口。

重点关注：

  • 默认网关；
  • 出口网卡；
  • Docker bridge；
  • VPN 虚拟网卡。

查看网卡 MTU 配置

探测链路真实 MTU

使用 ping 命令加上禁止分片标记（DF），不断调整包大小，测试出链路能通过的最大数据包，从而计算出全链路的真实 MTU 瓶颈值（ping 使用的是 ICMP 协议，请利用上文 ICMP 协议下的 MTU 计算公式）。
